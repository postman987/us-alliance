# Jobs API

## 실행 방법

- 실행

```
yarn run start
```

- seed 데이터 생성(1000건)

```
yarn run seed
```

- 테스트

```
yarn run test
```

## 제약 사항

### 서버

- 단일 인스턴스, 단일 프로세스 상의 node.js 서버를 운용한다고 가정
- 해당 인스턴스에서 jobs.json 파일을 관리

### 데이터

- 대략적으로 최대 100만건 정도의 job 데이터를 저장하여 관리하는 것으로 가정
- node-json-db를 통해 파일을 관리하고, node-json-db 특성상 각 요청에 대해 파일의 모든 데이터를 가져와 처리하기 때문에 성능을 고려하여 해당 수치를 가정
- 만약 해당 수치 이상의 데이터를 관리해야 한다면 다른 저장소를 사용하는 쪽으로 결정

### 스케줄러

## 설계

### 데이터 설계

- id는 유일한 uuid로 관리
  - api 요구사항으로 id를 통한 job 데이터 조작이 가능해야 하므로, 유일성을 보장할 수 있는 데이터 사용
- job의 id를 key로 사용하여 job 데이터를 관리
  - 특정 key를 기준으로 데이터를 조작하는 api 요구사항이 있어 key를 통한 search 방식이 효율적인 측면이 있음

### 동시성 제어

- node-json-db 내부적으로 데이터 접근시 mutex + queue를 적용한 동시성 제어가 적용되고 있어 이를 활용
- 다만, job list를 array로 관리하여 데이터 조회 이후 조작을 하면 key를 통해 데이터에 접근해 한번의 요청으로 데이터를 조작하는 것이 유리하다고 판단하여 job을 key를 기준으로 관리

### 철회한 결정

- completed jobs
  - 완료된 jobs를 completed jobs라는 다른 파일로 관리하는 아이디어
  - node-json-db 특성상 모든 전체 파일을 한번에 조작하기 때문에 기본적으로 조작하는 데이터 양을 줄여 성능을 높이기 위한 결정
  - 다만 데이터를 옮기는데 파일을 여러번 조작해야 하며, 조회시 2개의 파일을 search해야 하므로 폐기
